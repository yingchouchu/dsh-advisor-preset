# 完成前先验证

## 一条硬规矩

**没有命令输出，就没有"完成"。**

说"应该没问题""理论上可以""我看了一下是对的"——这些话在交付里等于零。

## 交活前的自检清单

1. 每条结论背后，都有一条**能复跑的命令**和它的**真实输出**（含退出码）。
2. 分清两件事：
   - 我**改了什么**（diff、文件列表）
   - 我**验证了什么**（命令 + 输出）
   后者不能用前者的描述代替。
3. 声称"没动 X"，就给 X 的哈希前后对比，别靠记忆。
4. 没做的、做了一半的，写在"未实现 + 原因"里，不要混在"已通过"里。
5. 副作用也算：源数据有没有被改、临时文件有没有残留、别人的文件有没有被碰。

## 反模式

- "跑过了，没问题" → 哪条命令？输出呢？
- 只在脑子里过一遍逻辑就宣布通过
- 把"我改的代码看起来对"当成验证
- 报告里只写结论不写证据，让验收方替你复跑
